# Prisma 7 — data access

Prisma 7 replaced the Rust engine with a **query compiler + driver adapters**.
Several things are different from Prisma ≤6.

## Key differences (Prisma 7)

- Config lives in **`prisma7.config.ts`** (NOT `prisma.config.ts` in 7.10), which
  imports `dotenv/config` and declares `schema`, `migrations.path`, `migrations.seed`,
  and `datasource.url`.
- `schema.prisma` keeps only `provider` in `datasource`; the URL is in the config.
- Generator is `prisma-client` with `output = "../src/generated/prisma"`. The
  client is generated as **TypeScript source** (gitignored).
- The client needs a **driver adapter**: `new PrismaClient({ adapter: new PrismaPg(...) })`.
- No auto-generate after `migrate` and no auto-seed — run `pnpm db:generate` and
  `pnpm db:seed` explicitly.

## Schema editing workflow

1. Edit `prisma/schema.prisma`.
2. `pnpm db:generate` — regenerate the client (required after every change).
3. `pnpm db:migrate -- --name <description>` — create + apply a migration.
4. `pnpm typecheck` — the client is `@ts-nocheck`, but our code that uses it is not.

## Using the client

```ts
import { prisma } from "@/lib/prisma"; // singleton — never `new PrismaClient` in app code

const users = await prisma.user.findMany({ where: { role: "teacher" } });
const student = await prisma.student.create({ data: { firstName, lastName, dateOfBirth } });
```

- Import types/enums from `@/generated/prisma/client` (server) and
  `@/generated/prisma/browser` or `@/generated/prisma/enums` (client-safe types only).
- `Prisma.validator()` is gone — use `satisfies Prisma.UserSelect`.
- Middleware (`$use`) is gone — use `$extends` with `query.$allModels`.

## Domain model (see `prisma/schema.prisma`)

- `User` — Better Auth + `role` (`manager` | `teacher`) and `phone`; relations to `Session`, `Account`. Teachers are users with `role = "teacher"`.
- `Student` (`students`) — `firstName`, `lastName`, `sex` (enum), `dateOfBirth`.
- `Guardian` (`guardians`) — `firstName`, `lastName`, `email`, `phone`, `address`.
- `StudentGuardian` (`student_guardians`) — M:N join with `relation`, `isPrimary`.
- `Room` / `Level` / `ClassSession` — managed lookup sets (classrooms, levels, weekend session slots).
- `SchoolClass` (`classes`) — name, description, required `levelId`, optional `roomId`, optional `teacherId` → `User`.
- `SchoolClassSession` (`class_session_links`) — M:N class↔session.
- `Enrollment` (`enrollments`) — student↔class join with `status` (`active`|`withdrawn`).
- `StudentComment` / `GuardianComment` / `ClassComment` — per-entity comments with `body` and optional `authorId` → `User`.

## Data access rules

- Go through `src/lib/prisma.ts` singleton.
- Call `requireSession()`/`requireRole()` from `src/lib/dal.ts` before queries
  in Server Actions / Route Handlers.
- Return DTOs (select only needed fields); never return `Account` or session rows.
- Use `cuid()` for domain-model ids (generated by Prisma); Better Auth manages
  its own `String @id` fields itself.
- Validate input with Zod or `@mantine/form` before writing to the DB.

## The driver adapter

```ts
// src/lib/prisma.ts
import { PrismaClient } from "@/generated/prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL! });
export const prisma = new PrismaClient({ adapter });
```

- `@prisma/adapter-pg` wraps `pg` (node-postgres). Pool options (`max`,
  `idleTimeoutMillis`, `ssl`) can be passed to `PrismaPg`.
- The singleton pattern prevents connection-pool exhaustion under `next dev`.
